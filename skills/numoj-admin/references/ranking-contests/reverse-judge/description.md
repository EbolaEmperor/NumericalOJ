# 反向评测：公开题目描述（Harbor 模板）

### 题目要求

你的任务是出一道题，让 AI 做不出来。AI 得分越低，你的得分越高！题目应该紧密结合本学期《算法与数据结构》课堂所学知识。

请提交一个 Harbor 格式的任务。支持上传 ZIP，或从比赛配置的 Git 仓库提交。典型任务结构如下：

```text
task.toml
instruction.md
environment/
  Dockerfile
solution/
  solve.sh
tests/
  test.sh
```

- `instruction.md`：完整题面和必要的函数、文件及输入输出接口；不写隐藏测试数量、分组或运维指引。
- `task.toml`：任务元数据、超时和资源配置；按需用顶层 `artifacts` 声明需要保存的作答产物，例如 `artifacts = ["/app"]`，也可省略或留空。
- `environment/Dockerfile`：准备任务所需工具、依赖、公开材料和初始文件。
- `solution/solve.sh`：在任务环境中完成题目的可执行参考解。反向评测要求提供参考解。
- `tests/test.sh`：验证入口；在同一作答环境中检查最终状态并写入数值奖励，仅在验证阶段由 Harbor 提供。

验证脚本将 `0` 到 `1` 之间的得分写入 `/logs/verifier/reward.txt`，其中 `1` 表示满分、`0` 表示零分。也可以使用 `/logs/verifier/reward.json` 输出多个有限数值指标；平台优先取 `reward`，其次取 `score` 作为 `0` 到 `1` 的主分。没有这两个字段时，仅在全部指标均为 `0` 到 `1` 时取平均值；耗时、损失等辅助指标保留原值，不显示为满分为 1 的得分项。隐藏测试数据应放在 `tests/`，参考解应放在 `solution/`，避免在任务初始环境中泄露答案。

任务格式与执行方式可参考 [Harbor 官方文档](https://docs.harborframework.com/tasks/overview)。旧的 `problem/`、`template/`、`judge.sh` 题目包已弃用。

### 评测流程

1. Harbor 执行 `solution/solve.sh` 并进行验证，参考解必须获得满分。
2. 若比赛启用了质量门禁，独立审核 Agent 检查提交的原始任务是否符合出题要求。
3. 使用你选择的 AI 作答节点，在任务环境中根据 `instruction.md` 完成题目。
4. Harbor 在该轮作答环境中执行验证脚本，记录 AI 的奖励值。若 AI 得分为 $r$，你的排行榜得分为 $(1-r)\times100$。`artifacts` 仅用于作答产物归档。

AI 的作答时限由比赛配置决定，提交前请查看页面上的可用节点和时限。你可以查看解题过程，并在作答完成后下载归档的产物。

### 基本原则

#### 一、答案必须可推导

正确答案必须能通过题面和公开材料推导出来。不得在参考解与验证脚本中隐藏题面未提供、也无法推导的密码或私有信息，以此让 AI 必然失败。

#### 二、评测必须确定、可复现

任务环境应提供所需依赖与数据。验证脚本应根据交付结果计分，并正常生成奖励文件。不得利用容器启动失败、验证异常、网络故障或不存在的工具取分。

#### 三、不得恶意浪费作答时限

题目应通过算法与推理难度挑战 AI。不得故意引导 AI 访问极慢或不存在的网站、反复执行无意义等待，或使用与任务无关的指令消耗时间。

#### 四、使用纯文字描述题目

避免要求 AI 依赖图片、视频或音频理解题意，也不得将多模态生成能力作为完成算法任务的前提。
