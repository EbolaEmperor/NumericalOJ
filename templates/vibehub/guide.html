DEVELOPER GUIDE / SCHEMA v1

把你的作品装进
一个离线容器

VibeHub 接受包含前后端与 Dockerfile 的完整 ZIP 程序包。平台负责构建、隔离、按需启动和回收。

01

PACKAGE

程序包结构

ZIP 解压后的根目录必须直接包含 Dockerfile 与 vibehub.json，不要再套一层文件夹。

my-work.zip
├── Dockerfile
├── vibehub.json
├── app/
│   ├── server.py
│   └── static/
├── cover.jpg
└── README.md
02

MANIFEST

作品清单

第一版协议固定使用 Unix Domain Socket。字段名和路径必须完全一致。

{
  "schema_version": 1,
  "transport": "unix",
  "socket_path": "/run/vibehub/app.sock",
  "health_path": "/healthz",
  "cover_image": "cover.jpg"
}

cover_image 必填且只接受包内真实 PNG/JPEG/WebP。平台会中心裁切并生成 1280×720、最多 400 KiB 的安全副本；原图不会被改写。不要声明 TCP 端口。

03

TRANSPORT

在 Socket 上提供 HTTP/1.1

容器启动命令需在 /run/vibehub/app.sock 监听 HTTP/1.1。平台会等待健康检查成功后才把作品交给玩家。

GET /healthz必须返回 HTTP 200 Content-Type按实际内容正确设置 相对资源静态文件不可假定站点根路径
04

ROUTING

尊重基础路径

代理请求会带上 X-VibeHub-Base-Path。页面中的链接、表单和资源地址应以该值为前缀，或全部使用相对 URL。

base_path = request.headers.get(
    "X-VibeHub-Base-Path", ""
)
# 推荐：HTML 中使用 ./assets/app.js
# 或拼接 base_path + "/api/state"
05

SECURITY BOUNDARY

作品必须完整离线运行

构建与运行阶段都不应依赖互联网。把依赖、字体、前端资源和运行时需要的数据放进程序包或基础镜像允许的范围内。

  • 无外部网络不能访问 API、CDN、包仓库或局域网服务。
  • 不注入密钥不要把 Token、密码或 Cookie 打进镜像。
  • 最小文件视图作品看不到 OJ 源码、上传目录或宿主系统文件。
  • 沙箱 iframe作品无法读取 OJ 页面 DOM 或取得同源权限。
06

RELEASE FLOW

开发版与公开版

上传会创建新的开发版本；作者可先试玩。提交审核并通过后，平台才会复制这一版作为新的公开版本。

  1. UPLOAD上传 ZIP生成开发版本
  2. PLAYTEST作者试玩容器按需启动
  3. REVIEW管理员审核检查内容与运行
  4. PUBLIC公开发布稳定副本独立保存
