# 动态平衡术

这是 `vibehub-edu/1` 协议的完整教学示例。作品自行定义题目、学生 API 和评分规则，
通过私有 `edu.sock` 返回成绩。平台绑定学生身份、冻结作品版本和操作快照，校验响应格式后
入账，不重新计算中位数或核验堆操作。

`app.py` 生成公开练习输入和独立隐藏输入，适配 `start`、`step`、`grade`。
`cpp.py` 提供堆 API 头文件、C++ 驱动、操作记录解析与重放、中位数和评分规则。
需要执行时，作品返回 `{execute, continuation}`；平台在现有作品容器中用随机不同 UID
编译、运行，再将可信 `execution_result` 交回同一接口。作品解释结果并决定展示状态或成绩，
不启动额外判题容器。清单无需 `executor`，以后修改签名、API 或规则只需更新作品。

学生实现 `double step(int x)`。`A` 是大顶堆，`B` 是小顶堆，均只提供 `insert(int)`、
`pop()`、`top()`、`size()`；`size()` 返回 `int`，空堆返回 0。调用之间全局状态保留。
每轮只按函数返回值是否等于当前中位数判定，不要求两堆的大小、元素分配或保存的元素集合。
偶数个元素时返回两个中间值的平均值。
堆元素仍是整数，返回值须为有限 `double`；求平均前先转换为 `double`。作品驱动以
`max_digits10` 精度记录返回值，避免整数截断或默认输出精度丢失。

试运行由作品解析真实 C++ 操作记录，用传送带及两棵二叉堆播放，遇到首个错误立即停下。
用于动画展示的 24 个公开输入互不重复；固定开头与随机部分之间也不会重复，同一种子保持相同序列。
传送带与两棵堆共用一个展示面板，正常播放不显示轮次、计数、返回值或状态小字，只在出错时提示。
页面进入时弹出任务及 API 说明，确认后将同一张卡片动画停靠在代码区下方。
错误轮次保留预期值、返回值和运行异常。
正式提交时平台冻结操作，作品取出源码、自行生成隐藏输入并重新执行评分，练习输入的通过
情况不直接计入成绩。浏览器传来的分数、完成标记或执行结果都不能替代私有评分响应。
公开浏览允许练习，只有作业入口绑定的作答可以记入老师的成绩表。
提交后编辑器仍可修改草稿，上一轮评测完成后才能再次试运行或提交。页面在需要时自动创建
新的作答并保留当前代码，无需点击额外按钮；原提交及其成绩继续保留，旧结果轮询不会覆盖新草稿。

Dockerfile 将 `/app` 设为 0700；服务启动时确认 `/data` 是作品 UID 拥有的真实目录并设为
0700，失败则拒绝启动。`/run/vibehub` 沿用运行时的 0770 权限。平台执行前验证这三个目录
对学生 UID 均不可读、不可遍历；执行从 `/tmp` 启动，保留只读根目录及 `noexec`，产物通过
匿名 memfd 运行。学生进程不能读取这些目录中的评分源码和未交给它的数据，也不能访问私有 socket。

旧包曾依赖 `cpp-heap-median-v1` 或 `cpp-heap-median-v2` 及 `context.execution`。
旧 `executor` 字符串现在只是元数据，不恢复旧执行能力。旧成绩和快照保留，但冻结包不会
自动迁移；尚未完成的旧作业需要作者发布兼容包，再由管理员明确重新布置。

页面复用站点的 Monaco 编辑器及 C++ 高亮。`cd frontend && npm run build:monaco`
会同时生成本示例的离线编辑器资源；更新依赖或编辑器入口后需重新生成并一并发布。
编辑器以相对路径加载，不依赖外部 CDN，不改变作品 iframe 的权限。
两个服务分别监听 `/run/vibehub/app.sock` 与 `/run/vibehub/edu.sock`。
运行和评分均不接收用户学号，学生身份绑定由平台完成。
