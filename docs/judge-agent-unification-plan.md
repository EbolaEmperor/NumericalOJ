# Judge 统一到通用 Agent 的计划

## 1. 已确定的产品设计

| 项目 | 最终决定 |
| --- | --- |
| 执行底座 | Agent Judge、Reverse Judge 质量门禁和 AI 作答，都像“解题”“造数据”一样创建通用 Agent 会话，复用执行、续聊、workspace、轨迹和用量统计 |
| 端点管理池 | 保留现有比赛端点池及管理页面；端点选择、排队、并发控制、健康检查、自动暂停和恢复均归端点池 |
| 任务发送 | 池放行后，把选好的端点信息、提示词和输入文件交给通用 Agent；支持比赛专有端点 |
| 队列与并发 | 只有一个通用 `agent` 队列，受全站并发数限制；比赛端点池并发已满时，任务留在比赛侧，不发送出去 |
| 会话分类 | 三类评测会话统一归为 `judge` 类别 |
| 会话列表 | 管理员可切换“全站会话、我的会话、Judge 会话”；Judge 会话单独放在仅管理员可见的栏中 |
| 普通用户可见性 | 看不到 Agent Judge 和质量门禁会话；只能查看自己提交的 Reverse Judge AI 作答会话 |
| 管理员可见性 | 可以查看全部 Judge 会话 |
| 人工发消息 | Judge 会话禁止人工发消息和插话，管理员也不例外；回复框保留，但不可编辑、不可发送 |
| 后端权限 | 直接访问 URL 或接口执行同样的查看鉴权；通过 POST、旧接口、重试或队列操作绕过禁发限制时，后端也要拦截 |
| 详情弹窗 | 保留评测状态、证据和结果，移除轨迹展示，按权限提供通用 Agent 会话链接 |
| 拓扑编排 | 保持原来的拓扑序串行执行，每完成一个 rule 就内部续聊下一条，复用同一会话、端点和 workspace |
| 文件处理 | 提供通用 workspace 文件注入和导出方法；复制需要的输入、导出需要的结果，不直接挂载用户上传的原始文件或目录 |
| 质量门禁 | 允许使用通用 Agent 的完整工具能力，使用独立的审核材料副本 |
| 提示词 | 同步改为通用 workspace 的路径和使用方式 |
| 费用 | 正式 Judge 费用计入全站，不扣减用户个人 Agent 额度 |
| 历史迁移 | 一次性脚本在下次 deploy 时将历史评测迁入通用会话，成功核验后删除脚本及部署调用 |
| 代码规模 | Judge 侧保留任务触发、业务编排、结果接收和记分；删除专用执行、隔离、挂载和轨迹处理逻辑，减少整体代码量 |

## 2. 端点池与队列

保留现有比赛端点池管理，包括端点选择、排队、并发控制、健康检查、自动暂停和恢复。Agent Judge 和质量门禁从对应池选点，Reverse Judge AI 作答使用用户选择的端点。

端点池放行后，将选好的端点信息、提示词和输入文件交给通用 Agent。端点可以是比赛专有端点；通用 Agent 使用指定端点执行，并向池反馈任务状态和结果。

- 比赛端点池并发已满：任务留在比赛侧等待，不发送给 Agent。
- 端点池允许发送：任务进入唯一的通用 `agent` 队列，与普通 Agent 一起受全站并发上限控制。
- 已发送但仍在通用队列等待的任务保留端点池名额，完成或取消确认后释放，避免超额发送。

比赛侧等待是业务状态，不设专用队列。端点健康和并发管理始终归端点池，通用 Agent 负责执行。

## 3. 会话展示与权限

三类评测会话统一归为 `judge` 类别。管理员的任务列表增加“Judge 会话”，形成“全站会话、我的会话、Judge 会话”三栏；Judge 会话单独展示，该栏仅管理员可见。

比赛详情弹窗保留评测状态、证据和结果，移除轨迹展示，改为按权限提供通用 Agent 会话链接。

| 会话 | 对应提交者 | 其他普通用户 | 管理员 |
| --- | --- | --- | --- |
| Agent Judge | 不可见 | 不可见 | 可见 |
| Reverse Judge 质量门禁 | 不可见 | 不可见 | 可见 |
| Reverse Judge AI 作答 | 可见 | 不可见 | 可见 |

普通用户从自己的 Reverse Judge 详情进入 AI 作答会话。直接访问 URL、请求会话接口、轨迹或 workspace 文件时，后端执行同样的鉴权。

所有 Judge 会话均禁止人工发消息和插话，管理员也不例外。回复框仍然展示，但不可编辑、不可发送。后端同时拦截 POST、旧接口及重试、队列操作等绕过方式；自动评测续聊通过内部业务入口发起。

## 4. workspace 与提示词

提供通用 workspace 文件注入和导出方法：把需要的文件复制到 workspace，执行完成后把需要的结果导出。所有 Judge 任务都使用这套方法，不直接挂载用户上传的原始文件或目录。

质量门禁使用完整工具能力。门禁获得完整审核材料，AI 作答只获得题面和模板；各阶段使用独立副本，避免修改原始材料或把标准答案带入作答会话。

Agent 直接在 `/workspace` 启动，除系统必需内容外只挂载通用 workspace；业务材料全部注入其中。反向作答将模板文件展开到 workspace 根目录，题面放在 `problem/`，整个公开 workspace 是交付目录。

提示词沿用统一前的任务要求，只调整目录结构和现行结果交付方式；以当前项目目录为视角使用相对路径，交付整个项目目录；删除专用挂载说明以及只读、禁止修改目录等权限声明。Agent Judge 的准备、依赖安装、运行诊断和证据要求，以及反向作答的完整交付要求都保留。历史补齐脚本中的旧模板只用于还原实际发送过的原文，不用于新任务。

## 5. 评测编排

Agent Judge 保持原来的拓扑序串行执行：先完成准备，每完成一个 rule，再通过内部续聊执行下一个 rule，复用同一会话、端点和 workspace。前置依赖判断及记分仍由后端负责，每次续聊都经过端点池放行。

Reverse Judge 保留“标准答案自检 → 质量门禁 → AI 作答 → AI 答案评分”的流程。质量门禁和 AI 作答分别使用独立的通用 Agent 会话。

## 6. 费用

正式 Judge 任务的费用计入全站费用，不扣减用户的个人 Agent 额度。用量和费用记录复用通用 Agent 的统计能力，并支持比赛专有端点。

## 7. 历史迁移

提供一次性迁移脚本，将现有历史评测记录、轨迹及可取得的 workspace 文件迁入通用会话，并保持上述访问权限。

脚本接入下次 `deploy.sh`，在停服、备份后执行。迁移应可重复执行且不重复创建会话或记账；历史缺失内容明确标记。迁移成功并核验后，删除脚本及部署调用。
