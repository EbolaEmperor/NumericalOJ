## 1. 随机选择算法

给定含有 $n$ 个不同数的数组 $A$ 和整数 $1\leq k\leq n$，考虑下面求第 $k$ 小元素的算法。

**算法 RandomSelect(A, k)**

```text
1. n ← A 的元素个数
2. if n = 1 then return A[1]
3. 从 A 中等概率随机选择一个元素 p
4. 将 A 中除 p 外的元素划分为：
       L：所有小于 p 的元素
       G：所有大于 p 的元素
5. ℓ ← L 的元素个数
6. if k = ℓ + 1 then return p
7. if k ≤ ℓ then return RandomSelect(L, k)
8. return RandomSelect(G, k - ℓ - 1)
```

第 4 行可通过一次扫描完成，处理长度为 $m$ 的数组需要 $\Theta(m)$ 时间。

1. 说明该算法为什么能够正确返回第 $k$ 小的元素。
2. 证明对于任意固定输入和任意合法 $k$，算法的期望时间复杂度为 $\Theta(n)$。
3. 给出一系列使算法花费 $\Theta(n^2)$ 时间的枢轴选择，并说明这为什么不与第二问矛盾。

**【要求：写出期望运行时间的递推关系，或给出等价的严格分析。不能仅用“枢轴平均位于中间”代替证明。】**

## 2. 有序数组上的随机枢轴查找

给定严格递增的数组 $A[1..n]$，目标 $x$ 是其中的一个元素。考虑下面的查找算法。

**算法 RandomSearch(A, x)**

```text
1. l ← 1; r ← n
2. while l ≤ r do
3.     从整数区间 [l, r] 中等概率随机选择 j
4.     if A[j] == x then return j
5.     if A[j] < x then l ← j + 1
6.     else r ← j - 1
```

设 $x=A[k]$，其中 $k$ 固定，算法事先不知道 $k$。令 $D$ 为 `while` 循环执行的总轮数，包含找到 $x$ 的最后一轮。记

$$
H_s=\sum_{i=1}^{s}\frac1i.
$$

1. 证明

   $$
   \mathbb E[D]=H_k+H_{n-k+1}-1.
   $$

2. 由此证明，对任意合法 $k$，该算法的期望时间复杂度为 $\Theta(\log(n+1))$。
3. 分析该算法的最坏时间复杂度，并与每次选择区间中点的普通二分查找比较。
