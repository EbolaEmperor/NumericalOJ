# Local verifier

任务：独立完成节点 `{node_id}` 的完整局部数学验证。输入为题面、全部原稿 PNG、本节点完整 statement 和全部直接前驱的完整 statements，不先拆成形式化、语义审计或证明搜索子任务。

必须查看全部原稿图片。图片用于核对作者实际数学意图、条件和证明方法，不能把图片中其他未列入的作者断言默认为可信前提。只允许使用列明直接前驱的完整命题和 goal 自身封装的局部条件；题面其他数学假设也不能暗中加入。全局定义和假设必须已作为 given 登记并连入本节点的直接前驱；不得因它们在题面、祖先或另一个分支出现，就在本任务中隐形继承。普通数学类型及逻辑规则用于忠实表达，不是新增假设。不读取转录、步骤、局部摘录或引文，不提取 PDF 文本或 OCR，不修改题面、图片或 DAG。

唯一责任是“全部直接前驱 statements 联合成立时，推出本节点完整 statement”；没有前驱时验证完整 statement。前驱 claim 可以作为此局部蕴含的条件，但并不表示它已成立；不能以某个前驱本身尚未证明为理由反驳该蕴含。待检对象保留全部前驱，不能逐边检验或只检验 goal 真值；证明无需人为使用逻辑上不必要的前提。前提为假时按蕴含实际逻辑处理，目标单独不成立不是 refuted。

先对照原稿图片和题面核对对象：完整定义、域、原量词及否定、依赖关系、条件方向、共同自由参数和同一见证的绑定。整个联合蕴含统一绑定共享对象，原命题内部已有量词保留自身作用域，不把各前驱分别全称化、不为各前驱另选见证。图片中的真实条件或数学对象被 DAG 漏掉或改变时，返回 graph_defect 并填写下方结构化 diagnostics，不替图补前提，也不把生成漂移算成学生错误。若 DAG 忠实保留作者未满足定理条件或不成立的推理，这是待验的证明问题，不得一律归为图缺陷。原稿自身确实无法确定定义或绑定时如实说明语义不确定，返回 inconclusive，不要求构图者猜测补全。

先区分记号的语义身份。无歧义的绑定变量改名不改变命题，应说明改名前后等价，不因这种记号差异停止。不得改变命题含义、依赖关系或变量绑定，也不得把真实语义差异当作笔误修正。疑似原稿笔误按实际数学含义核对；依据完整定义判断记号是否等价，不凭字形相似猜测。

原图与 DAG 必须保持相同的量词、作用域和绑定。原图的实际含义被 DAG 改变时返回 graph_defect，不自行补入更强前提。若 DAG 忠实表达了原稿推理，应验证这个完整推理，不能借图返修替作者补好数学缺口。Lean 中每项假设都必须对应原直接前驱或目标自身已有的局部条件；不得将尚需证明的内容设为额外假设，再把编译通过算为整个节点 passed。

自行选择适合完整命题的数值、符号计算、数学工具或 Lean 方法，独立搜索资料和 mathlib、编写代码、迭代执行直到完成或确认不能可靠判断。可以在同一任务内形成所需定义与忠实等价表示，但必须保持完整目标与前提，不增加假设或改成较弱的辅助命题。不给固定 SymPy 表达式协议，不派额外计算、形式化、语义审计或编译 Agent。

允许自主搜索、引用和使用已经成立的数学定理；定理不需要事先登记成 DAG 前驱，搜索定理不属于补假设。必须核对定理原陈述、全部适用条件、对象和量词，并说明这些条件如何从本任务直接前提或 goal 内部已有局部条件得到。不能把未满足的适用条件或尚需证明的内容设为新假设。外部定理的信息未显式列出本身不决定 verdict；先查明完整陈述及是否覆盖当前目标。找不到或无法核对可靠陈述时返回 inconclusive，不以搜索失败反驳数学命题。

使用数值或符号工具时，记录实际方法、结果及其为何决定整个局部蕴含。证据只能支持其实际覆盖的范围；存在不确定性时，必须说明它为何不影响所报结论。使用 Lean 时自行完成完整命题与证明，实际编译且确认退出码 0，不以声明可编译代替证明；不得使用 sorry、admit、axiom 或其他占位公理。编译通过后仍须核对 Lean 的 theorem 与完整自然语言蕴含在完整含义、量词、作用域、假设和依赖关系上对应；未证明完整目标或使用额外假设的 theorem 编译通过不允许 passed。无需核查版本号或 commit，不安装已有工具环境。Lean 编译可直接用工具完成，不是另一个 Agent 任务。

探索工作量大小本身不决定结论；证据未覆盖完整局部蕴含时不能返回 passed。计算前估算工作量，先小规模试跑，复用预计算；潜在长命令自主设置合适的工具 timeout（Pi bash 的 timeout 单位为秒），为完整推导与结果整理留出时间。命令超时后先调整方法或缩小探索规模，不原样重复巨型循环；超时本身不决定数学 verdict。这里不改变全站输出额度，也不新增模块执行上限。

passed 需要整个忠实局部蕴含成立的充分证据；refuted 需要满足全部原直接前提、域、量词和作用域而目标失败的可靠证据，或精确否定的完整证明；可确认的图偏移为 graph_defect；其余情况为 inconclusive。搜索失败、超时、不能读图、表示不清或生成漂移不能 refuted。refuted 只反驳这次局部联合推理，不能自动说明本节点命题或原题定理为假；passed 也不能自动认证尚未建立的前驱。

将完整但简洁的证据、实际工具操作、代码/输出路径与不确定边界写入 `faithsieve-work/verification/{node_id}.md`，不重述整份原稿，不编造执行记录。报告须说明原稿与待检蕴含是否对应、实际验证覆盖的量词和假设、使用的数学定理与适用条件、无歧义变量改名及证据为何决定完整目标。使用 Lean 时列出实际 theorem 的完整签名、必要定义与自然语言对象的对应关系和实际编译结果，不能只给文件路径或“编译通过”。数值反证须明确全部前提如何满足及误差为何不影响结论；一般性证明须给出可核对的完整数学论证。没有使用工具时不编造编译或计算记录；仅完成部分验证时明确缺口。

结果 JSON 精确为 status、artifact、report、diagnostics 四字段，不增加其他字段。将以下结构写入 `faithsieve-work/results/{node_id}-local-verifier.json`，选择实际状态，不把竖线枚举写入结果：

```json
{"status":"passed","artifact":"faithsieve-work/verification/{node_id}.md","report":"完整局部蕴含的验证结果与依据","diagnostics":[]}
```

status 只能是 passed、refuted、inconclusive 或 graph_defect。前面三种状态的 diagnostics 必须为 []；graph_defect 的 diagnostics 必须非空，每条精确包含 kind、affected_node_ids、reason。kind 只能是 statement_mismatch（命题或对象错抄）、missing_premise（原图明确给出的必要条件未进入局部前提）、quantifier_drift（量词或其作用范围改变）或 binding_mismatch（共同参数、已选见证或作用域绑定改变）。affected_node_ids 是非空、无重复节点 ID 数组，只写本目标或输入中已有的直接前驱 ID；reason 用中文明确原图实际数学含义与 DAG 的差异，不写原句引文、页码定位或局部摘录，不给作者添加新条件。

graph_defect 的 JSON 结构如下；诊断内容须填写实际可确认的原稿与 DAG 差异：

```json
{"status":"graph_defect","artifact":"faithsieve-work/verification/{node_id}.md","report":"目标与原稿的完整含义不一致，尚未验证该局部蕴含。","diagnostics":[{"kind":"statement_mismatch","affected_node_ids":["{node_id}"],"reason":"填写可确认的原稿与目标之间的语义差异。"}]}
```

图偏移诊断是供独立看图核对的事实说明，不自行修改 DAG，也不把它算作数学反证。不得因定理不在 DAG、前驱尚未证明、无歧义的绑定变量改名或仅仅搜索失败而输出 graph_defect。结果和报告保持一致，用标准 JSON 解析器核对元数据与 diagnostics 字段后再结束。
