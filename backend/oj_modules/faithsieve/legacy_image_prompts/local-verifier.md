# Local verifier

任务：独立完成节点 `{node_id}` 的完整局部数学验证。输入为题面、全部原稿 PNG、本节点完整 statement 和全部直接前驱的完整 statements，不先拆成形式化、语义审计或证明搜索子任务。

必须查看全部原稿图片。图片用于核对作者实际数学意图、条件和证明方法，不能把图片中其他未列入的作者断言默认为可信前提。只允许使用列明直接前驱的完整命题和 goal 自身封装的局部条件；题面其他数学假设也不能暗中加入。必要对象类型和定义用于忠实表达，不是新增假设。不读取转录、步骤、局部摘录或引文，不提取 PDF 文本或 OCR，不修改题面、图片或 DAG。

唯一责任是“全部直接前驱 statements 联合成立时，推出本节点完整 statement”；没有前驱时验证完整 statement。前驱 claim 可以作为此局部蕴含的条件，但并不表示它已成立；不能以某个前驱本身尚未证明为理由反驳该蕴含。待检对象保留全部前驱，不能逐边检验或只检验 goal 真值；证明无需人为使用逻辑上不必要的前提。前提为假时按蕴含实际逻辑处理，目标单独不成立不是 refuted。

先对照原稿图片和题面核对对象：完整定义、域、原量词及否定、依赖关系、条件方向、共同自由参数和同一见证的绑定。整个联合蕴含统一绑定共享对象，原命题内部已有量词保留自身作用域，不把各前驱分别全称化、不为各前驱另选见证。图片中的真实条件或数学对象被 DAG 漏掉或改变时，返回 inconclusive，指出图偏移，不替图补前提，也不把生成漂移算成学生错误。疑似原稿笔误按实际写法核对，不能静默修成正确命题。

原图不能替 DAG 增强前提或改变量词及其作用域。若 DAG 没有忠实登记原图中所需条件，返回 inconclusive 并说明图偏移，不能以“按原稿应如此理解”补入前提。Lean 中每项假设都必须对应原直接前驱或目标自身已有的局部条件；不得把所需的新前提或关键待证结论直接设为假设，再将辅助证明的编译通过算为整个节点 passed。

自行选择适合完整命题的数值、符号计算、数学工具或 Lean 方法，独立搜索资料和 mathlib、编写代码、迭代执行直到完成或确认不能可靠判断。可以在同一任务内形成所需定义与忠实等价表示，但必须保持完整目标与前提，不增加假设或改成较弱的辅助命题。不给固定 SymPy 表达式协议，不派额外计算、形式化、语义审计或编译 Agent。

使用数值或符号工具时，记录实际方法、结果及其为何决定整个局部蕴含。证据必须覆盖所报告结论的完整责任与适用范围，不能夸大证据支持的结论。使用 Lean 时自行完成完整命题与证明，实际编译且确认退出码 0，不以声明可编译代替证明；不得使用 sorry、admit、axiom 或其他占位公理。无需核查版本号或 commit，不安装已有工具环境。Lean 编译可直接用工具完成，不是另一个 Agent 任务。

验证范围必须与完整目标一致，不能以不完整的验证结果认定整个命题成立。计算前估算工作量，先小规模试跑，复用预计算；潜在长命令自主设置合适的工具 timeout（Pi bash 的 timeout 单位为秒），为完整推导与结果整理留出时间。命令超时后先调整方法或缩小探索规模，不原样重复巨型循环；超时本身不决定数学 verdict。这里不改变全站输出额度，也不新增模块执行上限。

passed 需要整个忠实局部蕴含成立的充分证据；refuted 需要满足全部原直接前提、域、量词和作用域而目标失败的可靠证据，或精确否定的完整证明；其余情况为 inconclusive。搜索失败、超时、不能读图、表示不清或生成漂移不能 refuted。refuted 只反驳这次局部联合推理，不能自动说明本节点命题或原题定理为假；passed 也不能自动认证尚未建立的前驱。

将完整但简洁的证据、实际工具操作、代码/输出路径与不确定边界写入 `faithsieve-work/verification/{node_id}.md`，不重述整份原稿，不编造执行记录。将 `{"status":"passed|refuted|inconclusive","artifact":"faithsieve-work/verification/{node_id}.md","report":"完整局部蕴含的验证结果与依据"}` 写入 `faithsieve-work/results/{node_id}-local-verifier.json`。结果和报告保持一致，标准 JSON 解析通过再结束。
