# Check-object generator

任务：将 `{obligation_path}` 中固定义务 `{obligation_id}` 忠实转换为检查对象，写入 `{check_object_path}`，不判断真假或重新生成义务。

读取固定主义务、本节点及全部直接前驱的完整命题，和必要题面、原稿来源。唯一局部责任为“全部直接前驱 statements 联合推出本节点完整 statement”。没有前驱时证明完整结论；前驱 claim 可以作为条件输入，但不表示它已经成立。不得拆成每条入边的任务，不追加 O2、桥梁任务或额外依赖。

按 source → 节点和直接前驱 → 固定主义务 → check 逐层核对。题面与原稿是来源，生成文件彼此一致不代表忠实。必要源条件被图漏掉、量词或对象已经漂移时，标明源位置并返回 inconclusive；不能补前提修复图、修正原稿，或将更强局部命题的失败计为学生错误。

原文声明的类型、记号和定义可用于表达对象；题面全文不能暗中提供未列入直接前驱的数学假设。数学输入只能是列明直接前驱和目标自身封装的局部条件。共享自由参数与原稿固定见证在整条蕴含中统一绑定，不逐个把前驱独立全称化，不让同一个符号指向不同对象。原命题内已有量词保持自身作用域，不能任意抽出、交换或加强。

逐项保留定义、域类型及附属性质、量词、依赖关系、否定、方向和见证身份。不能为了方便验证重定义对象、删除必要限制或加入源外前提；不得以未使用、其他文件一致或解释约定豁免漂移。忠实表达所需的纯定义展开或同一验证中已证明等价的表示可注明依据，但不引入新假设。无法完整保留本节点责任时返回 inconclusive，不能改为较弱条件命题。

选择 route=numeric 或 lean。numeric 是让验证 Agent 自主选择适合的计算或其他可靠方法验证整条蕴含，允许有直接前驱；验证必须覆盖完整局部责任，不扩大证据支持的结论范围，也不忽略前提的逻辑含义。需要 Lean 形式证明时选 lean。路由只选择方法，不能改变命题或预设结果。

写入 `{check_object_path}`：obligation ID、独立 route: numeric|lean 行、来源映射、完整前驱列表和 target、统一参数/定义/见证绑定、完整待检蕴含、路由理由及真实歧义。不生成证明，不改输入文件。

将 `{"status":"ok|inconclusive","artifact":"{check_object_path}","report":"忠实性、验证方法及歧义"}` 写入 `faithsieve-work/results/{obligation_id}-check-object-generator.json`。确认 JSON 可解析且字段准确。完成后简短说明文件已写入。
